# Native coverage: reconciliation of the LLVM PDB documents

This page is part of the [native coverage](../native-coverage.md) accounting. It covers `docs/reference/llvm/llvm/` at LLVM `b9f2235f`.
Each section names one imported document. Paths are relative to `docs/reference/`. The fields are:

- **Documents**: the format items that the document describes.
- **pdbrs**: `implemented` (pdbrs reads every item that the document describes), `partial`, `not implemented` or `not applicable` (no format content), with the source files.
- **Conflicts**: each difference between the document and pdbrs, or between the document and another source (`cvinfo.h`, LLVM source, `ms-pdb`, other documents). Errors inside the document are conflicts too.
- **Undocumented assumptions**: layouts and rules that pdbrs uses but the document does not state, with the issue that records the evidence.

The comparison used `main` at `8dc001c`, `cvinfo.h` at `805655a2`, LLVM at `b9f2235f` and the `ms-codeview` 0.1.7, `ms-pdb` 0.1.22, `ms-pdb-msf` 0.1.7 and `ms-pdb-msfz` 0.1.10 crates. "Inference, not tested" marks a statement that comes from reading source code only. Source paths are relative to `crates/pdbrs/src/native/` unless they start with `crates/`.

### `llvm/llvm/docs/PDB/index.md`
- Documents: The PDB file layout overview: the MSF container, the fixed streams 0–4, the named streams `/LinkInfo`, `/src/headerblock` and `/names`, the DBI-referenced module, public and global streams, the TPI/IPI hash streams, and the CodeView record pages.
- pdbrs: implemented — pdbrs reads and writes every stream role in the table. Stream 0: `msf/old_directory.rs`. Stream 1: `info.rs`, `info/builder.rs`. Streams 2/4 and their hash streams: `types.rs`, `types/hash.rs`, `types/write.rs`. Stream 3: `dbi.rs`, `dbi/*.rs`. Module streams: `dbi/module.rs`, `dbi/module/*.rs`, `lines.rs`, `lines/*.rs`, `codeview/symbol*.rs`. GSI/PSI and the symbol record stream: `symbols.rs`, `symbols/*.rs`. Optional debug streams: `debug_stream.rs`, `debug_stream/*.rs`, `fpo.rs`, `section.rs`. `/LinkInfo` versions 1 and 2: `auxiliary/link_info.rs`. `/src/headerblock`: `injected_source.rs`, `injected_source/builder.rs`. `/names`: `names.rs`, `names/builder.rs` (hash versions 1 and 2). `native::PdbBuilder` writes a new PDB with all roles (`write.rs`, `write/*.rs`, #33). `native::PdbEditor` changes a PDB and rebuilds the indexes (`edit.rs`, `edit/*.rs`, #34). `crates/pdbrs/examples/native/` reads all roles, joins them and encodes them again.
- Conflicts:
  - index.md vs DbiStream.md and pdbrs: the table says the Public Stream and the Global Stream hold "Symbol Records" and an "Index of Public/Global Hash Stream". The records are in the symbol record stream (`DbiStreamHeader::SymRecordStream`). The GSI/PSI streams hold the hash table themselves; no separate hash stream exists. pdbrs reads the records from the symbol record stream and the hash tables from the GSI/PSI streams (`symbols.rs`).
  - index.md omits the symbol record stream from the stream table.
  - index.md says `/LinkInfo` contents are "Unknown". pdbrs decodes and encodes `/LinkInfo` from Microsoft `pdb.h` `struct LinkInfo` and `dbi.cpp` `GetUTF8LinkInfo` (`auxiliary/link_info.rs`, #32). Versions 1 (`vliOne`) and 2 (`vliTwo`) use the same layout. MSVC `link.exe` 14.51 writes version 2; no available producer writes version 1, so its tests are synthetic. LLVM writes an empty stream.
  - index.md omits named streams that pdbrs reads: `/TMCache` (`auxiliary/tm_cache.rs`), the type map streams that `/TMCache` names (`auxiliary/type_map.rs`), `/UDTSRCLINEUNDONE` (`auxiliary/udt_source_line_undone.rs`), `sourcelink` (`auxiliary/source_link.rs`), `srcsrv` (`auxiliary/source_server.rs`) and `/src/files/*` (`injected_source/document.rs`, `injected_source/natvis.rs`). pdbrs decodes and encodes the first three. By the scope decision of #32, pdbrs keeps `sourcelink`, `srcsrv` and Natvis files as classified bytes: it checks the text form and splits `srcsrv` into sections and lines. It does not interpret Source Link JSON, Natvis XML or `srcsrv` variables and commands.
  - index.md omits the DBI optional debug streams (FPO, new FPO, section headers, OMAP and others) from the table; it mentions only "FPO / PGO Data" in the DBI row. pdbrs decodes and encodes all 11 slots (`debug_stream.rs`, #32).
  - index.md vs MSVC `link /PDBSTRIPPED` and pdbrs: the table lists `/names` as a stream of every PDB. The stripped PDB of `msvc-x64-stripped` has no `/names` stream (#27). pdbrs reads a PDB without `/names` (#32). `PdbEditor::strip_private` removes `/names`, except when a new FPO stream refers to it (#34).
  - index.md says the PDB Stream holds the "Fields to match EXE to this PDB". The image match uses the GUID of the PDB Info stream and the age of the DBI header (see the `PdbStream.md` section).
- Undocumented assumptions:
  - Stream 0 policy for writing (#15): `OldDirectoryPolicy::Empty` (default, stream 0 present with length 0, as LLD and `ms-pdb-msf`) or `Preserve` (same page size only). `PdbEditor` writes an empty stream 0 with the page size of the source (#34).
  - Stream IDs of a new PDB (#33): `PdbBuilder` assigns streams 0 to 4, then the TPI and IPI hash streams, the GSI, the PSI, the symbol record stream, the module streams in module order, the optional debug streams in slot order, the named streams in the order of their addition and the other streams. A semantic rebuild drops nil streams.
  - Stream IDs of an edited PDB (#34): each source stream keeps its ID. A removed stream becomes a nil stream. A new stream gets the next ID after the last source stream. The plan copies each unchanged stream without a decode.
  - `/names` hashing and growth (#32): version 2 uses `hash_string_v2` (Microsoft `HasherV2`, LLVM `hashStringV2`). Both versions reduce the hash modulo `0xffffffff` before the reduction modulo the bucket count (`NMT::hashSz`, `names.rs:62-73`). `StringTableBuilder` follows Microsoft `NMT`: 1 bucket and a buffer with one NUL; after each new name, if `buckets * 3 / 4 < names`, the table gets `buckets * 3 / 2 + 1` buckets and the names go in again in the old bucket order (`names/builder.rs:1-18`). LLVM selects a larger count (709 buckets for 242 names, where `NMT` gives 472) and orders colliding names by its internal map; pdbrs encodes a decoded LLVM table with the same bytes.
  - `/TMCache` layout (version `0x20200229`, 20-byte header, `u16` stream table, 16-byte entries) and type map stream versions 1 and 2, from `mspdbcore.dll` `DBI1::DumpTMCache` evidence (#13).
  - `/UDTSRCLINEUNDONE` is a `u32` type index list; no reference defines it (#9).

### `llvm/llvm/docs/PDB/MsfFile.md`
- Documents: The MSF 7.00 container: the 56-byte-prefix SuperBlock, the two free block maps and their intervals, the stream directory, and the rule that fields can cross block boundaries.
- pdbrs: implemented — reader `msf.rs`, `msf/directory.rs`, `msf/free_page_map.rs`, `msf/old_directory.rs`; writer `msf/write.rs`, `msf/write/layout.rs`, `msf/write/emit.rs`, `msf/write/builder.rs`, `msf/write/file.rs`. `PdbBuilder` (#33) and `PdbEditor` (#34) lay out their output with `MsfBuilder`. The reader accepts every power of two from 512 to 65536 (`MAX_PAGE_SIZE`, `msf.rs:72`). The writer accepts 512 to 32768 and returns `UnsupportedVersion` for 65536 (`MAX_WRITE_PAGE_SIZE`, `msf/write/layout.rs:20-37`). The reader rejects the small MSF 2.00 container with `UnsupportedVersion` (legacy #16).
- Conflicts:
  - MsfFile.md vs LLVM `MSFCommon.h` and pdbrs: the document says valid block sizes are 512, 1024, 2048 and 4096, and that "LLVM only supports 4096 byte blocks". LLVM `isValidBlockSize` accepts 512 to 32768, and `getMaxFileSizeFromBlockSize` gives file limits for 8192–32768. The pdbrs reader accepts 512 to 65536. The pdbrs writer accepts 512 to 32768 (#15).
  - MsfFile.md vs pdbrs reader vs `ms-pdb-msf`: 65536-byte pages. `ms-pdb-msf` 0.1.7 and the pdbrs reader accept them. LLVM ("Unsupported block size."), DIA2Dump (`HRESULT 806D000C`) and `link.exe /PDBPAGESIZE:65536` (`LNK1399`) reject them (#15). The document does not mention 65536.
  - MsfFile.md vs `ms-pdb-msf` and pdbrs: offset 48 is `Unknown` in the document. `ms-pdb-msf` names it `stream_dir_small_page_map` (MSPDB `mpspnpn`). pdbrs ignores it on read and writes 0.
  - MsfFile.md vs pdbrs: `BlockMapAddr` is one `u32` block index. MSPDB/`ms-pdb-msf` and pdbrs treat offset 52 as an array of page-map page numbers (`stream_dir_big_page_map`). The pdbrs reader and writer accept more than one page-map page if the array fits in the header page (`msf/directory.rs:71-77`, `msf/write/layout.rs:98-104`). LLVM `validateSuperBlock` rejects that file ("Too many directory blocks."). A pdbrs writer output with a directory of more than `page_size/4` pages is thus not readable by LLVM.
  - MsfFile.md vs pdbrs reader: the document says `NumBlocks * BlockSize` should equal the file size. The pdbrs reader requires the declared pages to fit and ignores bytes after them (`msf.rs:16`, `:246-249`).
  - MsfFile.md vs LLVM `MSFCommon.h`: the pdbrs writer checks only that the page count fits in `u32`. It does not apply LLVM `getMaxFileSizeFromBlockSize` (4 GiB at ≤ 4096-byte pages). (Inference, not tested: no such check found in `msf/write/*`.)
  - Errors inside the document:
    - "the second block of each FPM refers to the next 8 blocks" is wrong. It refers to the next 8 intervals (the next 32768 blocks at 4096-byte blocks).
    - The `uint16` split example has the bytes reversed. In little-endian order the low byte is in the last byte of block N and the high byte is in the first byte of block N+1.
    - "The file consists of ... `SuperBlock::BlockSize - 3` blocks of data" uses BlockSize as a block count. This is correct only because the interval length equals the block size in blocks; the document does not state this rule.
- Undocumented assumptions:
  - Nil stream size `0xFFFFFFFF` in the stream directory (`NIL_STREAM_SIZE`, `msf.rs:66`); a nil stream has no pages. Not in the document.
  - The directory size must be a multiple of 4 and at least 8 bytes; the stream count must be nonzero; the page lists must fill the directory exactly (`msf/directory.rs`).
  - No page reference can name page 0 or page `p` with `p % page_size` in {1, 2}; no page can occur twice (`msf.rs:157-162`, `msf/directory.rs` `check_unique`).
  - FPM read rule: the active FPM is `ceil(page_count/8)` bytes across pages `active + k*page_size`; a set bit is a free page; stream 0 pages can be free or allocated; unreferenced allocated pages are reported, not errors (`msf/free_page_map.rs`, #9).
  - Writer layout (#15): pages in ascending order (stream pages by stream ID, then directory, then page map); if the last page is the first page of an interval, the writer adds that interval's FPM pages; active FPM is 1; FPM2 is all `0xFF`; bytes after the bitmap are `0xFF`; unused bytes are zero; the default page size is 4096.
  - A preserved stream 0 needs the source page size; otherwise `InvalidFormat` before output (#15 addendum).
  - `PdbEditor` keeps the page size of the source and returns `UnsupportedVersion` before output for a source page size that the writer does not support (65536) (`edit/plan.rs:262-264`, #34).

### `llvm/llvm/docs/PDB/PdbStream.md`
- Documents: The PDB Info stream: the header (version, signature, age, GUID), the version enum, the named stream map (string buffer and hash table), the feature codes and the PDB/EXE match rule.
- pdbrs: implemented — decoder and `Info::encode` in `info.rs`; `InfoBuilder`, `IdentityPolicy` and `PeMatch` in `info/builder.rs` (#32). pdbrs decodes version VC70 (20000404) only; other values of the version enum are `UnsupportedVersion` (`info.rs:133-135`). It decodes the signature, the age, the 16 GUID bytes, the string buffer, the hash table (`hash_table.rs`, `hash_table/owned.rs`), `niMac` (`Info::next_name_index`) and the feature codes as typed `Feature` values (`Vc110`, `Vc140`, `NoTypeMerge`, `MinimalDebugInfo`, `Unknown`, `info.rs:38-78`). `MINI` selects the GSI/PSI bucket count (`BucketCount`, `symbols.rs:97-137`).
- Conflicts:
  - PdbStream.md vs LLVM `NamedStreamMap.cpp` and Microsoft `nmtni.h` and pdbrs: the document says the feature codes follow the named stream map directly. LLVM reads and writes a `u32` `NMTNI::niMac` after the hash table (`NamedStreamMap.cpp:62-63`, `:80-82`). pdbrs reads it as `next_name_index` and starts the features after it (`info.rs:174-175`). LLVM writes 0 there (`info.rs:235-237`). An earlier pdbrs build followed the document and reported `niMac` as feature code 0 (defect fixed in #9).
  - PdbStream.md vs LLVM `NamedStreamMap.cpp` and pdbrs: the document says the bucket hash is the hash of the string. LLVM `NamedStreamMapTraits::hashLookupKey` truncates `hashStringV1` to 16 bits (`NMTNI::hash`). pdbrs uses `hash_string_v1(name) & 0xffff` and checks the linear-probing placement of each name (`info.rs:159-163`).
  - PdbStream.md vs MSPDB and pdbrs: `MinimalDebugInfo` says "There is no TPI / IPI stream". The document does not say that the feature also changes the GSI/PSI bucket count to `0x3ffff` (MSPDB `GSI1::GSI1`). pdbrs uses this rule (`BucketCount::from_features`). pdbrs does not change TPI/IPI handling for `MINI`; the claim about absent TPI/IPI streams was not checked against the FASTLINK fixture.
  - PdbStream.md vs pdbrs: LLVM `InfoStream::reload` stops at VC110 and skips unknown words. pdbrs keeps all words as `Feature` values, also unknown codes, and requires the remaining length to be a multiple of 4 (`info.rs:174-178`).
  - PdbStream.md vs `pdbstr` and pdbrs (age): the document says the Info `Age` and the GUID match the PDB to the image, and that the linker increments the Info `Age`. The DBI header has a second age. pdbrs matches the image with the GUID and the DBI age (`reader.rs:221-223`, `info/builder.rs:27-28`). `pdbstr -w` increments only the Info age (`msvc-x64-srcsrv/demo.srcsrv.pdb`: Info age 2, DBI age 1, #27). The pdbrs reader accepts an Info age that is larger than the DBI age and rejects a DBI age that is larger than the Info age (`reader.rs:227-238`, #32).
- Undocumented assumptions:
  - Duplicate names in the named stream map are `InvalidFormat` (`info.rs:164-172`).
  - The named-stream hash table layout rules come from `HashTable.md` plus LLVM `HashTable::load` checks (see `HashTable.md` section).
  - Feature `0x494E494D` (`MINI`) selects 262143 GSI/PSI buckets (#8, #13).
  - `InfoBuilder` inserts names with the rules of Microsoft `NMTNI` (`map.h`) or LLVM `NamedStreamMap` (`HashTableProducer`). Both named-stream maps start with 1 bucket (LLVM `OffsetIndexMap(1)`, `hash_table/owned.rs:21-22`). The Info stream that `InfoBuilder` rebuilds from its names gives the same bytes in all 29 native fixture PDBs (#32).
  - `IdentityPolicy` (#32): `Preserve` keeps the GUID, the signature and the ages and rejects a DBI age that is larger than the Info age; `IncrementAge` adds 1 to the Info age and writes it to the DBI header; `Replace` sets the signature, the GUID and one age for both streams. Each policy returns `PeMatch` (GUID and DBI age) for the `RSDS` entry of the image (`info/builder.rs:307-347`). `Preserve` after a semantic edit keeps the image match; the editor documentation warns about this (#34).

### `llvm/llvm/docs/PDB/TpiStream.md`
- Documents: The TPI (stream 2) and IPI (stream 4) layout: the TPI/IPI record split, type index encoding with simple-type kinds and modes, the 56-byte header with version enum, the hash stream buffers (hash values, index offsets, hash adjusters) and the record list.
- pdbrs: implemented — `types.rs` (header V80 only, `HEADER_SIZE` 56, hash key size 4, buckets 0x1000..=0x40000), `types/hash.rs` (`TypeHashes`, `type_record_hash`, `verify`, `parse_adjusters`), `types/lookup.rs` (O(1) table, index-offset lookup), `types/forward.rs` (forward reference resolution), `types/validate.rs` (`validate_type_references`), `types/write.rs` (`write_type_stream`, `HashLayout`, `serialize_hash_adjusters`), `codeview/index.rs` (primitive type decoding). Records: `codeview/type_record.rs`, `codeview/field_list.rs`, `codeview/id_record.rs`; every modern leaf decodes and encodes (#29). The rebuilt TPI and IPI streams and their hash streams are identical to the originals in 28 fixture PDBs (#29). Not implemented: the auxiliary hash stream (`hash_aux_stream` is a stream number only; the writer copies the number), versions V40/V41/V50/V70 (`UnsupportedVersion`, `types.rs:349-352`).
- Conflicts:
  - TpiStream.md vs Microsoft `tpi.cpp` (`mpnitiHead`), LLVM `DumpOutputStyle.cpp` and pdbrs: the document says hash adjuster keys are hash values. Microsoft and LLVM read the keys as `/names` offsets of UDT names; values are type indices. pdbrs `HashAdjuster { name_offset, index }` follows the implementations (`types/hash.rs:52-58`, #3).
  - TpiStream.md vs `cvinfo.h` (`CV_MMASK 0x700`) and LLVM `TypeIndex.h` (`SimpleModeMask 0x700`): the diagram gives Mode bits 8–11 (4 bits). The mode is bits 8–10; bit 11 is reserved. pdbrs reads byte 1 and accepts only modes 0–7 (`codeview/index.rs:36-54`, `:95`), so a set bit 11 is `InvalidFormat`.
  - TpiStream.md vs pinned `cvinfo.h`: the document lists `Character8 0x7c`, `Boolean128 0x34`, `Complex16 0x56`, `Complex32PartialPrecision 0x55` and `Complex48 0x54`. The pinned `cvinfo.h` does not define them (LLVM `TypeIndex.h` does). pdbrs accepts them (`codeview/index.rs` `PrimitiveKind`).
  - TpiStream.md vs `cvinfo.h` and pdbrs: the document omits `T_ABS 0x01`, `T_SEGMENT 0x02`, `T_CURRENCY 0x04`, `T_NBASICSTR 0x05`, `T_FBASICSTR 0x06`, `T_BIT 0x60`, `T_PASCHAR 0x61`, `T_BOOL32FF 0x62` and `T_NCVPTR 0xf0` (`T_32NCVPTR`, `T_64NCVPTR`). pdbrs decodes them, with sizes, signedness and calling conventions (#29). `T_NCVPTR` is valid only with pointer modes 1 to 6 (`codeview/index.rs:44-52`, `:304-306`). #28 found that `0xf0` did not decode; #29 fixed it.
  - TpiStream.md vs LLVM `TypeIndex.h` and pdbrs: the document says a type index with bit 31 set comes from the IPI. LLVM names this `DecoratedItemIdMask`. pdbrs has no decoration handling; such an index is out of range for `IdTable::validate` and `TypeTable::record`. [INFERENCE from `codeview/index.rs` and `codeview/id_record/table.rs`.]
  - TpiStream.md vs pdbrs: "HashKeySize - usually 4 bytes". pdbrs requires exactly 4 (`types.rs:409-415`). The document also does not give the bucket limits; LLVM `TpiStream.cpp` and pdbrs both require 0x1000..=0x40000.
  - Errors inside the document: `TypeEndBegin` (twice) should be `TypeIndexBegin`; `HashBufferLength` should be `HashValueBufferLength`.
  - TpiStream.md vs pdbrs: the document says the records form a topologically sorted DAG. `validate_type_references` accepts a reference to the same or a later record (a forward reference) and counts it, because the format does not forbid it. With forward references, it searches for a cycle and returns `InvalidFormat` for one (`types/validate.rs:11-17`, `:122`, #29). Microsoft and LLVM writers write no forward references.
- Undocumented assumptions:
  - The hash value of each record is `type_record_hash(record) % buckets` (LLVM `hashTypeRecord`): UDTs use `hash_string_v1` of the name, or of the unique name for scoped types; forward references and anonymous UDTs use the CRC (`hash_buffer_v8`); `LF_UDT_SRC_LINE`/`LF_UDT_MOD_SRC_LINE` hash the 4-byte UDT index; others hash the full record. The wide forms `LF_CLASS2`..`LF_INTERFACE2` (0x1608–0x160b) hash as UDTs (`types/hash.rs:577-626`, #3, #29).
  - The three hash buffers must tile the hash stream without gaps or overlaps; index offset pairs must be strictly sorted and name record starts (#3).
  - Forward reference resolution follows LLVM `findFullDeclForForwardRef` (#2).
  - Hash stream producer forms (`HashLayout`, `types/write.rs:42-87`, #29): Microsoft (`tpi.cpp`) writes the hash values, the index offsets and the hash adjusters, adds an index offset pair when a record start enters a later 8 KiB block (`TPI1::RecordTiOff`), and writes offset 0 and length `0xffffffff` for each buffer without a hash stream. LLVM (`TpiStreamBuilder`) puts the empty adjuster buffer at the end of the hash values, adds a pair when a record end is in a later 8 KiB block than its start (`updateTypeIndexOffsets`), and writes length 0 without a hash stream. `HashLayout::of` selects the form from a header.
  - Hash adjusters serialize as Microsoft `Map::save` after `Map::add` in the given order: 1 slot at the start, the low 16 bits of the key as the hash, linear probing, growth at `count >= slots * 2 / 3 + 1` (`serialize_hash_adjusters`, #29). No fixture has adjusters; tests check this layout against the pdbrs reader only.

### `llvm/llvm/docs/PDB/DbiStream.md`
- Documents: The DBI stream: the 64-byte header (version enum, build number, flags, machine), the module info records, the section contribution versions, the section map, the file info substream, the type server map, the EC substream and the 11 optional debug stream slots.
- pdbrs: implemented — `dbi.rs` decodes the header (signature −1 and V70), all seven substream ranges and the EC substream as a `/names` string table (`names.rs`). `dbi/header.rs`: every header field, with flag accessors (incremental, stripped, C types) and build number accessors (new format, major, minor). `dbi/module_info.rs`: every module record field, with the first section contribution, the flag bit fields (written, EC, type server index) and the EC name indices. `dbi/section_contribution.rs`: V60 (28 bytes), V2 (32 bytes) and headerless SC40 (20 bytes). `dbi/section_map.rs`: header and 20-byte entries with `SegmentFlags`. `dbi/sources.rs`: file info with summed counts. `dbi/type_server.rs`: type server map records. `dbi/debug_header.rs` and `debug_stream.rs`, `debug_stream/*.rs`, `fpo.rs`, `section.rs`: all 11 optional debug stream slots. `address.rs` and `debug_stream/omap.rs`: OMAP translation in both directions. Each substream has an encoder; `DbiBuilder` (`dbi/builder.rs`, `dbi/write.rs`) builds a stream (#32). Not implemented: DBI versions VC41/V50/V60/V110 (`UnsupportedVersion`, `dbi.rs:148-162`), and the unwind information in the Xdata blob (raw bytes).
- Conflicts:
  - DbiStream.md vs LLVM `RawTypes.h` (`MachineType`, "See PDB_MachineType enum") and pdbrs: the document says `Machine` is a `CV_CPU_TYPE_e` value. The field holds `IMAGE_FILE_MACHINE_*` values; the document's own examples (`0x8664`, `0x14C`) are PE machine values. pdbrs documents `machine` as the `IMAGE_FILE_MACHINE` value (`dbi/header.rs:43-44`).
  - DbiStream.md vs pdbrs and `pdbstr` (age): the document says the DBI `Age` is "Equal to the same field from the PDB Stream header". `pdbstr -w` writes Info age 2 and keeps DBI age 1 (#27). The pdbrs reader accepts an Info age that is not smaller than the DBI age (`reader.rs:221-238`). `IdentityPolicy` writes the same age to both streams (#32).
  - DbiStream.md vs `cvinfo.h` (`tagFRAMEDATA`), LLVM `DbiStream.cpp` (`initializeNewFpoRecords` reads `DebugFrameDataSubsectionRef`) and pdbrs: the document says slot 9 (New FPO) is a debug directory of type `IMAGE_DEBUG_TYPE_FPO`. Slot 9 holds 32-byte `FRAMEDATA` records; slot 0 holds 16-byte `FPO_DATA` (`IMAGE_DEBUG_TYPE_FPO`). pdbrs decodes slot 0 as `FpoData` and slot 9 as `FrameData` with frame programs in `/names` (`fpo.rs:1-17`). The document's sentence ".debug$F sections are only emitted by MASM" is attached to the wrong slot.
  - LLVM `COFF.h` `object::FpoData` vs `winnt.h` `FPO_DATA` and pdbrs (FPO slot 0, not described in the document): LLVM reads `cbProlog` as bits 0–3, `fHasSEH` as bit 9 and `fUseBP` as bit 10. `winnt.h` and pdbrs use `cbProlog` bits 0–7, `cbRegs` bits 8–10, `fHasSEH` bit 11, `fUseBP` bit 12, `reserved` bit 13, `cbFrame` bits 14–15 (`fpo.rs:48-52`). Fixture evidence: 7 of 8 x86 FPO records have attribute word `0x0800`; pdbrs follows `winnt.h` (#13).
  - DbiStream.md vs Microsoft `dbi.h` and pdbrs (slots 1 and 2): the document says the streams are debug data directories of type `IMAGE_DEBUG_TYPE_EXCEPTION` and `IMAGE_DEBUG_TYPE_FIXUP`. MSPDB `DbgFunc1` stores 12-byte `IMAGE_FUNCTION_ENTRY` records (`pdb.h` marks the slot deprecated), and `DbgXFixup1` stores 12-byte `XFIXUP_DATA` records (`u16` type, `u16` extra, RVA, target RVA). pdbrs follows `dbi.h` (`debug_stream/function.rs`, `debug_stream/fixup.rs`, #32). `pdbtool` agrees on 2,793 fixups (#32).
  - DbiStream.md vs Microsoft `dbi.h` and pdbrs (slot 6): the document says the Token / RID map layout "is not understood". `DbgTokenRidMap` stores an array of `ULONG` values. pdbrs keeps the values (`debug_stream.rs:89-113`). No fixture has the stream; tests are synthetic (#32).
  - DbiStream.md vs Microsoft `pdb.h` and pdbrs (slots 7 and 8): the document says the streams are copies of the `.xdata` and `.pdata` sections, and that slot 8 would then equal slot 1. Each stream starts with the 32-byte `DbgRvaVaBlob` header (`ver` 1, `cbHdr`, `cbData`, `rvaDataBase`, `vaImageBase`, two reserved words); the section bytes follow. Slot 8 holds `RUNTIME_FUNCTION` entries; slot 1 holds `IMAGE_FUNCTION_ENTRY` records, so the two differ. pdbrs decodes the header and the x64 and ARM64 `RUNTIME_FUNCTION` entries (`debug_stream/blob.rs:1-24`, #32; fixtures `msvc-x64-debugtype` and `msvc-arm64-debugtype`, #27).
  - DbiStream.md vs DIA and pdbrs (slots 3, 4 and 10): the document gives no record layout and no lookup rule. pdbrs reads 8-byte `OMAP_DATA` records and translates with the rules of DIA: the last record with `rva <= address`; no mapping before the first record, after the last record or for `rvaTo == 0` (`debug_stream/omap.rs:1-24`, `address.rs`, #32).   - CodeViewSymbols.md vs pdbrs: for `S_PUB32` the document says the DBI section map gives the module of an address. The section contribution substream gives the module; the section map gives segment descriptors. pdbrs translates addresses with the section headers, the section map and OMAP (`address.rs`) and keeps the module index in `SectionContribution::module`. `SymbolLocator` finds the procedure, the source lines and the inline chain of an RVA or a section offset (`locate.rs`, #30).
  - CodeViewSymbols.md vs `cvinfo.h` and pdbrs: a scope runs "up until the next `S_END` record". Scopes nest; `S_INLINESITE` ends with `S_INLINESITE_END`, and `S_*PROC32_ID` can end with `S_PROC_ID_END`. pdbrs follows the parent/end links and checks the closer kind (`ModuleSymbols`, #5). `ModuleSymbolWriter` computes the links again when it writes (#30).
  - Error inside the document: the `S_REGREL32_INDIR` example table shows name bytes `7900` ("y") but the decoded row says `"a"`.
  - LLVM `CodeViewRecordIO::mapVectorTail` vs pdbrs (def-range gaps): LLVM stops reading gaps at the first gap whose first byte is ≥ 0xF0 (it treats it as `LF_PAD`). pdbrs returns all gaps; 47 sample records had hidden gaps (#5).
  - CodeViewSymbols.md vs pinned `cvinfo.h`: `S_FASTLINK` 0x1167, `S_INLINEES` 0x1168, `S_REGREL32_INDIR` 0x1171 and `S_DEFRANGE_REGISTER_REL_INDIR` 0x1177 are not in the pinned `cvinfo.h` (it ends at `S_RECTYPE_LAST` 0x1165; `S_RECTYPE_MAX` 0x1166 is a marker). LLVM `CodeViewSymbols.def` uses 0x1166 for `S_FRAMEREG`. pdbrs decodes `S_FRAMEREG` 0x1166 as a record, not as the old marker.
  - The document gives no hex value for `S_GDATA32` (0x110d) and no layout for most listed kinds (TODO headings).
  - Missing kinds vs `cvinfo.h`/LLVM `.def`: the document omits many kinds, for example `S_SKIP` 0x0007, `S_OEM` 0x0404, `S_MANSLOT` 0x1120, `S_GMANPROC` 0x112a, `S_LMANPROC` 0x112b, `S_TOKENREF` 0x1129, `S_ARMSWITCHTABLE` 0x1159, `S_FRAMEREG` 0x1166, `S_REGREL32_ENCTMP` 0x1179, `S_ANNOTATION`, `S_SEPCODE`, `S_INLINESITE2`, `S_POGODATA`, `S_REF_MINIPDB`, `S_PDBMAP`, the HLSL kinds, `S_MANYREG*`, `S_HOTPATCHFUNC` 0x1169, `S_BPREL32_INDIR` 0x1170, `S_GPROC32EX` 0x1172, `S_ASSOCIATION` 0x117c and `S_HYBRIDRANGE` 0x117d. pdbrs decodes and encodes all of them (#30). A scan of all 65536 kind values checks the decoders (`tests/symbol_encoding`, #30).
- Undocumented assumptions:
  - Layouts of the kinds above 0x1168 (#30): the pinned references do not give them. The debug type records of `cvinfo.h` in the DIA SDK of Visual Studio 18 (`lib/amd64/diaguids.lib`, read with `llvm-readobj --codeview`) give `PROCSYM32EX` (the `PROCSYM32` layout with a 2-byte `CV_EXPROCFLAGS`), `BPRELSYM32INDIR`, `REGREL32INDIR`, `STATICLOCAL`, `HYBRIDRANGESYM`, `DEFRANGECONSTVAL_ON_ENTRY`, `DEFRANGEGLOBALSYM_ON_ENTRY`, `REFMINIPDB2`, `SOURCELINKSYM` and the typedefs of the `_ENCTMP` kinds (`symbol/procedure.rs:11-14`, `symbol/storage.rs:8-13`, `symbol/code.rs:9-11`, `symbol/defrange.rs:3-8`, `symbol/linker.rs:4-7`).
  - `S_FASTLINK` (0x1167; LLVM comment "also known as S_REF_MINIPDB2"): `u32` value, `u16` flags, NUL-terminated name; flag bits 0 local, 1 data, 2 UDT, 3 label, 4 constant (from `REFMINIPDB`), bit 5 `fThunk` and bit 6 `fNamespace` (DIA SDK `REFMINIPDB2`; bit 6 also observed). Value: object-file type index if the UDT bit is set, else the 1-based COFF section number of the `.debug$S` section (`symbol/link.rs:6-13`, #13, #30).
  - `S_FRAMEREG` (0x1166): `u16` register then 2 zero bytes (#13).
  - `S_REGREL32_ENCTMP` (0x1179): the `S_REGREL32` layout (#13); the DIA SDK typedefs confirm it (#30).
  - `S_DEFRANGE_REGISTER_REL_INDIR`: `OffsetInUdt` is `i32` (LLVM `little32_t`); `S_REGREL32` offset is `u32` (#5). `S_REGREL32_INDIR` uses the field order of the document example: offset, type, offset in UDT, register, name (`symbol/storage.rs:182-224`).
  - Record padding (#30): any number of zero bytes can follow the fields; a byte that is not zero is `InvalidFormat`. `Symbol::padding` keeps the count, so `Symbol::encode` writes the same bytes; `SymbolData::encode` writes the shortest padding (`symbol.rs:514-539`). `fxc.exe` writes four or more zero bytes after an `S_LOCAL` name (fixtures `hlsl-fxc-sm50-debug`, #27). `S_COMPILE3` keeps the extra NUL bytes after the version string in `trailing_zeros` (`ml64` writes one more NUL). `S_SECTION`/`S_CALLSITEINFO` reserved fields must be zero (#5).
  - Thunks with a non-standard ordinal keep the variant bytes raw (`symbol/procedure.rs:429-435`, #5).
  - Managed records follow `cvinfo.h` `#pragma pack(1)`; `S_MANSLOT` holds a metadata token, not a TPI index; `S_OEM` with GUID `c6ea3fc9-59b3-49d6-bc25-0902bbabb460` decodes Roslyn `MD2` and `asyncMethodInfo` attributes (#14).
  - `S_SEPCODE` validation (#30): the validation accepts a def-range of a procedure in the range of a later `S_SEPCODE` whose parent address is the procedure start, and parameters in `S_SEPCODE` scopes (`symbol/validate/module.rs:31-33`, `:345-357`; MSVC PGO fixture, #27).
